Chunk 1 · Meet whileE5-PRO-VD-?? ⚠

The growing charm

for counts. while watches: it checks its question at the top of every pass, and runs the indented lines only while the answer is yes.

power = 10
while power < 50:
    power = power + 10
    print(power)
print("The charm is charged.")
Predict Trace it: what numbers print, and does 50 itself appear? When does the last line finally run?
20, 30, 40, and yes, 50 prints. The check happens at the top: 40 is still less than 50, so the loop runs once more, pours in 10, and prints 50. Only then does the check fail and the charm announce itself. The question is asked before each pass, never after.

Chunk 2 · Misfire on purposeE5-PRO-TR-?? ⚠

The unending curse, and how to stop it

A while must move toward no. Break that law on purpose, once, so you know the counter-curse. Before you run this, find the stop control: the square stop button in the terminal's corner, or click in the terminal and press Ctrl+C.

power = 10
while power > 0:
    power = power + 10
    print(power)
Predict Read the question and the pour. Will the answer ever become no? What is going to happen when you run this?
Never. power starts above 0 and only grows, so the question stays yes forever and numbers pour down the terminal until you end it. Stop it now: the square button, or Ctrl+C. This is the unending curse, and every programmer casts it by accident sometimes. The counter-curse is a habit: before running any while, point at the line that moves it toward no. If you can't find one, don't run it.
You should see 
20, 30, 40, 50... climbing forever until you press stop.
Then the terminal reports the spell was interrupted.
Chunk 3 · The ward of differenceE5-PRO-RD-?? ⚠

!= means "not the same"

Yesterday == asked "are these the same?" Its shadow twin != asks "are these different?" Every sentinel gate is built on it.

secret = "emberlight"
print(secret == "emberlight")
print(secret != "frostveil")
print(secret != "emberlight")
Predict Three answers will print. Write all three before you run.
True, True, False. The last one trips people: secret != "emberlight" asks "is the secret different from emberlight?", and it isn't, so the answer is no. Read != out loud as "is not" and it stops being slippery.

Chunk 4 · Pattern: the sentinel gateE5-PRO-TR-?? ⚠

Ask until the right word is spoken

The classic while pattern: keep asking while the answer is wrong. The exit is a word, not a count.

secret = "emberlight"
guess = input("Speak the word: ")
while guess != secret:
    print("The door does not stir.")
    guess = input("Speak the word: ")
print("The door swings open.")
Predict Guess wrong twice, then right. How many times does "The door does not stir." print? Which line moves the loop toward no?
Twice, once per wrong guess. The line that moves it toward no is the second input(), inside the loop: it refills guess so the question can change its answer. Delete that line and you've cast the unending curse with extra steps; the door would ask once and sulk forever.

Speak the word: frostveil
The door does not stir.
Speak the word: gloomvine
The door does not stir.
Speak the word: emberlight
The door swings open.
Chunk 5 · Pattern: the patient counterE5-PRO-VD-?? ⚠

Count the attempts

Yesterday's counter pattern moves into the sentinel gate: a vessel that grows by 1 every pass.

secret = "emberlight"
attempts = 1
guess = input("Speak the word: ")
while guess != secret:
    attempts = attempts + 1
    guess = input("Speak the word: ")
print(f"The door opens after {attempts} attempts.")
Predict Guess wrong twice, then right. What number does the door report, and why does attempts start at 1 instead of 0?
It reports 3: the first ask happens before the loop, so it's attempt 1, and each wrong guess adds one more. Start attempts at 0 and the door would undercount by one, an off-by-one hiding inside a while. Same old misfire, new costume.
You should see (wrong, wrong, right) 
Speak the word: frostveil
Speak the word: gloomvine
Speak the word: emberlight
The door opens after 3 attempts.
Chunk 6 · Pattern: ask-until-validE5-PRO-RD-?? ⚠

The stockroom won't hear nonsense

Day 1's shelf meets today's while: keep asking until the request is actually on the shelf.

shelf = ["moonpetal", "ashroot", "dewbark"]
ask = input("Which ingredient do you seek? ")
while ask not in shelf:
    print("That is not on the shelf.")
    ask = input("Which ingredient do you seek? ")
print(f"Fetch the {ask}.")
Predict Ask for gloomvine, then ashroot. What prints? Could this loop ever run zero times?
One refusal, then the fetch line. And yes: ask for something valid on the very first try and the question is no immediately, so the loop body never runs at all. A while that runs zero times isn't broken; it's a gate that didn't need to close. Real programs use this exact pattern every time a form says "please enter a valid answer."

Chunk 7 · The endless castingE5-PRO-RD-?? ⚠

The real game loop: while running

This is the pattern under every game ever made, in five beats: watch, listen, update, draw, breathe. The wisp drifts until you close the window; closing it is the exit.

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Wisp")
clock = pygame.time.Clock()

x = 0
running = True
while running:                          # 1. watch
    for event in pygame.event.get():    # 2. listen
        if event.type == pygame.QUIT:
            running = False
    x = x + 3                           # 3. update
    if x > 640:
        x = 0
    screen.fill((45, 27, 78))           # 4. draw
    pygame.draw.circle(screen, (240, 180, 41), (x, 240), 20)
    pygame.display.flip()
    clock.tick(60)                      # 5. breathe

pygame.quit()
Predict Which line moves this while toward no, and what do you do to trigger it? What happens to the wisp when x passes 640?
The exit is running = False, and you trigger it by clicking the window's close button; that arrives as a QUIT event, the listener catches it, and the watch question turns no. Until then the wisp drifts right 3 pixels per frame and wraps to 0 when it passes the edge. Every game you've played is this loop with more inside it, and the Day 4 engine is this loop with lists.

A golden wisp gliding left to right across the violet

Chunk 8 · The wobbleE5-PRO-PD-?? ⚠

Chance inside the loop

One line of chance-magic makes the wisp alive. Add an import at the top, a y vessel by x, and one update line inside the loop.

import random

# near the top, next to x:
y = 240

# inside the loop, right after x = x + 3:
y = y + random.randint(-2, 2)

# and draw at (x, y) instead of (x, 240)
Predict What will the wisp's path look like now? Over a long drift, will it stay near the middle or wander off?
It trembles as it drifts, nudged up to 2 pixels up or down every frame. And it wanders: the nudges don't cancel out on purpose, so over time the wisp can float far from 240. That wandering has a grand name, the random walk, and the Day 4 engine's sparks wobble with this exact line.
You should see 
The wisp still glides right, but now it trembles and
slowly wanders up or down as it goes.
Hinge question · stop here until you're sureE5-PRO-VD-?? ⚠

The overshooting charm

Without running it: charge = 5, then while charge < 30: charge = charge + 10 with a print(charge) inside the loop.
What numbers print, and what does charge hold when the loop ends?

15, 25, 35 print, and charge ends at 35. The check at the top sees 25 < 30, says yes one last time, and the pour overshoots the target. A while can land past its own finish line; if you need to stop exactly at a value, the question has to account for the size of the pour. If you traced all three numbers, the Unending Charms are yours.
Build brief · The Night Watch

Guard the door, then walk the sky

Part A, the Vigil (terminal): a door with your own secret word, a sentinel while gate, an attempts counter, and an f-string report when it opens. Then add the shelf: after the door opens, ask-until-valid for an ingredient from a 4-flask list.

Part B, the Wandering Wisp (window): your own wisp in the endless casting: your color, your speed, your wobble. It must name its exit: closing the window ends it cleanly.

Suggested start: Part A's door first, counter second, shelf third. House law: one change per run, and point at every while's exit line before you run it.

import pygame, random

# --- Part A: the Vigil ---
secret = "gloamlight"
shelf = ["moonpetal", "ashroot", "dewbark", "silverleaf"]

attempts = 1
guess = input("Speak the word: ")
while guess != secret:
    attempts = attempts + 1
    guess = input("Speak the word: ")
print(f"The door opens after {attempts} attempts.")

ask = input("Which ingredient do you seek? ")
while ask not in shelf:
    print("That is not on the shelf.")
    ask = input("Which ingredient do you seek? ")
print(f"Fetch the {ask}. The watch begins.")

# --- Part B: the Wandering Wisp ---
pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Night Watch")
clock = pygame.time.Clock()

x = 0
y = 240
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    x = x + 4
    if x > 640:
        x = 0
    y = y + random.randint(-2, 2)
    screen.fill((16, 8, 34))
    pygame.draw.circle(screen, (196, 120, 255), (x, y), 18)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()
Two whiles with word exits, one with a window exit. Every one of them can point at the line that moves it toward no.
