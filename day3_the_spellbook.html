Chunk 1 · Write it once, cast it twiceE5-PRO-RD-?? ⚠

def: a spell stored, not spoken

def writes a spell into your spellbook. Writing it down casts nothing. The spell fires only when you call its name.

def academy_greeting():
    print("* * * * * * * * *")
    print("  SPELL PREPARED")
    print("* * * * * * * * *")

academy_greeting()
academy_greeting()
Predict How many banners print? And if you deleted the two calls at the bottom and ran only the def block, what would print?
Two banners, one per call. Delete the calls and nothing prints at all. A def is ink in a book: nothing happens until you call it. Most apprentices guess wrong here, which is exactly why we run the experiment.

Chunk 2 · The blank in the spellE5-PRO-RD-?? ⚠

A parameter, filled at casting time

A parameter is a vessel that belongs to the spell: empty in the book, filled the moment you cast. It is Day 1's vessel, poured by the call instead of by =.

def cast(spell):
    print(f"Casting {spell}!")

cast("emberlight")
cast("frostveil")
Predict Write both output lines exactly. During the second call, what value sits inside the vessel spell?
During the second call, spell holds "frostveil". Same spell, refilled vessel. Write the def once and you can cast it as many times as you like, which is the reason functions exist.

Chunk 3 · Two blanks, filled in orderE5-PRO-RD-?? ⚠

Position pours the vessels

With two parameters, the wand fills them by position: first argument into the first vessel, second into the second. Watch what the swapped call does.

def brew(potion, doses):
    print(f"Prepare {doses} doses of {potion}.")

brew("moonpetal tonic", 3)
brew(3, "moonpetal tonic")
Predict Write both output lines exactly. Is the second call a misfire, or something quieter and worse?
No misfire. The wand happily pours 3 into potion and the tonic into doses, then prints nonsense with a straight face. Argument order carries the meaning. And a program that's quietly wrong is more dangerous than one that crashes; remember this one at Friday's Clinic.

Prepare moonpetal tonic doses of 3.

Chunk 5 · Growing a shelfE5-PRO-VD-?? ⚠

append: today's one new list move

Day 1's shelves were written by hand. append adds a flask to the end of a shelf, so a loop can grow one. The engine builds its spark shelves exactly this way.

shelf = []
for i in range(3):
    shelf.append(i * 12)
print(shelf)
print(len(shelf))
Predict The shelf starts empty. What exactly is inside after the loop, and what does len report? What would shelf[0] be?
[0, 12, 24], and len reports 3. Each pass appends i * 12, so flask 0 holds 0, flask 1 holds 12, flask 2 holds 24; the flask numbers are Day 1's law, unchanged. An empty shelf plus a loop of appends is how programs build collections they can't write by hand.

Chunk 6 · First Casting of the engine5.G.A.2

Wandlight: run it before you touch it

Open wandlight_pygame.py, or copy every line below into a file with that exact name. Change nothing. Run it. That's the gate: the engine has to run unmodified on your wand before tomorrow's Commission begins.

import pygame, random

pygame.init()
WIDTH = 640
HEIGHT = 480
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("Wandlight")
clock = pygame.time.Clock()

# ---------- THE ENCHANTMENT PANEL (your customizations live here) ----------
SPARK_COLORS = [(240, 180, 41), (250, 245, 235), (196, 120, 255)]
SPARK_COUNT = 40
RISE_SPEED = 2

WAND_TIP_X = WIDTH // 2
WAND_TIP_Y = 400
SKY = (45, 27, 78)
# ---------------------------------------------------------------------------

# Parallel lists: spark number i is xs[i], ys[i], speeds[i], sizes[i], colors[i]
xs = []
ys = []
speeds = []
sizes = []
colors = []

for i in range(SPARK_COUNT):
    xs.append(WAND_TIP_X + random.randint(-6, 6))
    ys.append(WAND_TIP_Y + random.randint(0, 30))
    speeds.append(RISE_SPEED + random.randint(0, 2))
    sizes.append(random.randint(2, 5))
    colors.append(random.choice(SPARK_COLORS))

def draw_wand(surface):
    pygame.draw.line(surface, (240, 180, 41),
                     (WAND_TIP_X + 60, HEIGHT - 20),
                     (WAND_TIP_X, WAND_TIP_Y), 6)
    pygame.draw.circle(surface, (250, 245, 235),
                       (WAND_TIP_X, WAND_TIP_Y), 5)

frame = 0
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill(SKY)
    draw_wand(screen)

    for i in range(SPARK_COUNT):
        ys[i] = ys[i] - speeds[i]              # rising: y gets SMALLER
        xs[i] = xs[i] + random.randint(-1, 1)  # the wobble
        if ys[i] < 0:                          # past the top: respawn at the tip
            xs[i] = WAND_TIP_X + random.randint(-6, 6)
            ys[i] = WAND_TIP_Y
        pygame.draw.circle(screen, colors[i], (xs[i], ys[i]), sizes[i])

    pygame.display.flip()
    frame = frame + 1            # counts the casting; timed gates read it
    clock.tick(60)

pygame.quit()
Predict Three predictions before you run. (1) What ends this casting, and on which day did you learn that loop? (2) The wand tip sits at (320, 400). As a spark rises, does its y value get bigger or smaller? (3) What happens to a spark whose y passes 0?
(1) You do, by closing the window: the QUIT letter arrives, the listener flips running, and the watch question turns no. It is Day 2's five-beat loop, holding forty sparks. (2) Smaller. On a screen, y counts downward from the top edge, so rising means y shrinking toward 0. (3) It respawns at the wand tip and rises again. Reading what a coordinate pair means in this particular situation is the skill the hinge is about to check.

Chunk 7 · Reading I: the frame ring5.G.A.2

Find the patterns you already own

Read the heart of the engine, the lines inside the frame loop. Don't run anything. Every marked line is a pattern you learned this week, wearing engine robes.

    for i in range(SPARK_COUNT):
        ys[i] = ys[i] - speeds[i]              # line A
        xs[i] = xs[i] + random.randint(-1, 1)  # line B
        if ys[i] < 0:                          # line C

Predict Name the pattern each line wears. Line A: which Day 2 charm is this, and what makes it unusual? Line B: whose magic from Day 1? Line C: which Day 1 trial?
Line A is the accumulator, running in reverse: it pours out a little each frame, and a shrinking y is a rising spark. Line B is Day 1's chance-magic, nudging x left or right: the wobble. Line C is Day 1's flat gate, the respawn decision. Nothing in the engine's heart is new. You could have written every line of it; the engine's only trick is doing it forty sparks at a time, sixty times a second.
Chunk 8 · Reading II: the five shelvesE5-PRO-VD-?? ⚠

How the engine builds its sparks

Now read the setup, above the loop. Five empty shelves, one growing loop. Spark number i lives at flask i on every shelf: that's the parallel-lists trick, and Day 2's orbs-from-a-list was its rehearsal.

xs = []
ys = []
speeds = []
sizes = []
colors = []

for i in range(SPARK_COUNT):
    xs.append(WAND_TIP_X + random.randint(-6, 6))
    ys.append(WAND_TIP_Y + random.randint(0, 30))
    speeds.append(RISE_SPEED + random.randint(0, 2))
    sizes.append(random.randint(2, 5))
    colors.append(random.choice(SPARK_COLORS))
Predict After this loop runs with SPARK_COUNT = 40: what is len(colors)? Is every colors[i] guaranteed to come from SPARK_COLORS, and why? Which chunk of today taught the growing move?
len(colors) is 40, one append per pass, and every colors[i] must come from SPARK_COLORS because random.choice only ever hands back an item from the shelf it's given, Day 1's law. The growing move is Chunk 5's append. Read the whole engine now, top to bottom, and initial every section you can explain; tomorrow's Commission begins where your initials stop.
Hinge question · stop here until you're sure5.G.A.2

The rising number

One frame runs the line ys[i] = ys[i] - speeds[i].
After it, is the spark drawn higher or lower on the screen, and is the number in ys[i] bigger or smaller than before?

Higher on the screen; smaller in the vessel. If you said "higher and bigger," you're using math-class axes on a screen that counts from the top. Re-read Chunk 6's second reveal before the build. If you got both, you're ready to rehearse for the Commission.
Build brief · The Spellbook Rehearsal

Write spells, then draw with one

Part A, the spellbook (terminal): write two spells of your own, one with one parameter, one with two, and cast them from a shelf with a loop, the way Chunk 4 did.

Part B, the drawing spell (window): rebuild Day 2's constellation through a def: write draw_orb(surface, x, size) and call it in a loop. Tomorrow your Commission asks for exactly this move with a sigil of your own.

Suggested start: Part A's one-parameter spell first. House law: one change per run.

import pygame

# --- Part A: the spellbook ---
def cast(spell):
    print(f"Casting {spell}!")

def brew(potion, doses):
    print(f"Prepare {doses} doses of {potion}.")

spellbook = ["emberlight", "frostveil", "glimmerstep"]
for spell in spellbook:
    cast(spell)
brew("moonpetal tonic", 2)

# --- Part B: the drawing spell ---
pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Rehearsal")

def draw_orb(surface, x, size):
    pygame.draw.circle(surface, (240, 180, 41), (x, 240), size)

screen.fill((45, 27, 78))
for i in range(5):
    draw_orb(screen, 70 + i * 125, 12 + i * 6)
pygame.display.flip()
pygame.time.wait(3000)
pygame.quit()
Part B is Day 2's constellation rule handed to a spell: the def holds the how, the loop holds the where. Trace the sizes before you run: 12, 18, 24, 30, 36.
