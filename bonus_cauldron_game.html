The Cauldron Game

Your first Marvel rose from a wand. Your second one plays. Orders arrive as two colored orbs, your keys throw flasks from the shelf, and the bell rings in thirty seconds. Brew what's asked and the stars pile up; throw the wrong flask and the brew spoils, the order resets, and you're back at it. How many potions can you fill in one shift?

Chunk 1 · First CastingE5-PRO-PD-?? ⚠

Play it before you read it

Open cauldron_pygame.py, or copy the full listing below into a file with that exact name. Change nothing. Run it and play one shift. Keep the terminal visible beside the window; the story narrates there while the game plays here.

import pygame, random

pygame.init()
WIDTH = 640
HEIGHT = 480
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("The Cauldron Game")
clock = pygame.time.Clock()

# ---------- THE BREWMASTER'S PANEL (your customizations live here) ----------
INGREDIENTS = [(240, 180, 41), (196, 120, 255), (120, 200, 255),
               (4, 120, 87), (250, 245, 235), (194, 65, 12)]
NAMES = ["gold", "lilac", "sky", "green", "parchment", "ember"]
POTIONS = ["Moonlight Draught", "Emberheart Tonic", "Gloamlight Elixir"]
NEED_A = [2, 5, 1]        # each potion needs flask NEED_A[p]...
NEED_B = [0, 3, 4]        # ...and flask NEED_B[p], in either order
GAME_FRAMES = 1800        # 1800 frames at 60 per second = a 30-second shift bell
SKY = (45, 27, 78)
# ----------------------------------------------------------------------------

def draw_shelf(surface):
    for i in range(6):
        pygame.draw.circle(surface, INGREDIENTS[i], (70 + i * 100, 440), 24)

def draw_cauldron(surface):
    pygame.draw.rect(surface, (20, 12, 40), (250, 300, 140, 60))
    pygame.draw.circle(surface, (20, 12, 40), (320, 300), 72, 8)

score = 0
target = random.randint(0, 2)
thrown = []
flash = 0
flash_color = SKY
time_bar = 600
frame = 0
running = True

print("=== THE CAULDRON GAME ===")
print("Orders arrive at the top of the window: two colors, one potion.")
print("Keys 1 to 6 throw the shelf flasks, left to right.")
print("Wrong flask? The brew spoils and the order starts over.")
print(f"First order: {POTIONS[target]}, {NAMES[NEED_A[target]]} + {NAMES[NEED_B[target]]}!")

while running:
    choice = -1
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        if event.type == pygame.KEYDOWN and event.key == pygame.K_1:
            choice = 0
        if event.type == pygame.KEYDOWN and event.key == pygame.K_2:
            choice = 1
        if event.type == pygame.KEYDOWN and event.key == pygame.K_3:
            choice = 2
        if event.type == pygame.KEYDOWN and event.key == pygame.K_4:
            choice = 3
        if event.type == pygame.KEYDOWN and event.key == pygame.K_5:
            choice = 4
        if event.type == pygame.KEYDOWN and event.key == pygame.K_6:
            choice = 5

    if frame < GAME_FRAMES and choice > -1 and choice != NEED_A[target] and choice != NEED_B[target]:
        print(f"The {NAMES[choice]} flask doesn't belong! The brew spoils...")
        thrown = []
        flash = 20
        flash_color = (90, 90, 100)
    if frame < GAME_FRAMES and choice > -1 and (choice == NEED_A[target] or choice == NEED_B[target]) and choice not in thrown:
        thrown.append(choice)

    if NEED_A[target] in thrown and NEED_B[target] in thrown:
        score = score + 1
        flash = 30
        flash_color = INGREDIENTS[NEED_A[target]]
        print(f"{POTIONS[target]} brewed! Score: {score}")
        thrown = []
        target = random.randint(0, 2)
        print(f"New order: {POTIONS[target]}, {NAMES[NEED_A[target]]} + {NAMES[NEED_B[target]]}!")

    if flash > 0:
        screen.fill(flash_color)
    else:
        screen.fill(SKY)
    if flash > 0:
        flash = flash - 1

    draw_cauldron(screen)
    draw_shelf(screen)
    pygame.draw.circle(screen, INGREDIENTS[NEED_A[target]], (280, 60), 22)
    pygame.draw.circle(screen, INGREDIENTS[NEED_B[target]], (360, 60), 22)
    for i in range(len(thrown)):
        pygame.draw.circle(screen, INGREDIENTS[thrown[i]], (300 + i * 40, 300), 14)
    for s in range(score):
        pygame.draw.circle(screen, (240, 180, 41), (20 + s * 24, 20), 8)
    if frame % 3 == 0 and time_bar > 0:
        time_bar = time_bar - 1
    pygame.draw.rect(screen, (240, 180, 41), (20, 468, time_bar, 6))

    pygame.display.flip()
    frame = frame + 1
    if frame == GAME_FRAMES:
        print(f"The bell rings! Final score: {score} potions. Close the window when you're ready.")
    clock.tick(60)

pygame.quit()
print(f"Kitchen closed. {score} potions this shift.")
Predict Before you run: how long is one shift, computed from the panel? The shift ends and the window ends: are those the same moment? And which day taught you the loop this game runs on?
Thirty seconds: 1800 frames at 60 per second. And no, they are not the same moment: the bell ends the shift by freezing the kitchen, but the window is Day 2's watched loop and stays open, score on display, until you close it yourself. Score a few potions, spoil a brew on purpose, and notice the spoil costs you the order, never the game.

Chunk 2 · The recipe shelvesE5-PRO-RD-?? ⚠

Three potions on five parallel lists

The engine keeps its rules the same way it kept its sparks: parallel lists, Day 3's trick. Potion number p is POTIONS[p], and it needs flask NEED_A[p] and flask NEED_B[p], in either order.

INGREDIENTS = [(240, 180, 41), (196, 120, 255), (120, 200, 255),
               (4, 120, 87), (250, 245, 235), (194, 65, 12)]
NAMES = ["gold", "lilac", "sky", "green", "parchment", "ember"]
POTIONS = ["Moonlight Draught", "Emberheart Tonic", "Gloamlight Elixir"]
NEED_A = [2, 5, 1]
NEED_B = [0, 3, 4]
Predict Read the shelves, then answer from the lists alone: which two flask colors brew the Emberheart Tonic, and which keys throw them? Is there any flask no potion ever uses?
Potion 1 needs flasks 5 and 3: ember and green, thrown by keys 6 and 4. And check the two need-lists together: flasks 0 through 5 all appear exactly once across them, so every flask matters to exactly one potion. That's a design choice you can break on purpose in your own version; a flask no recipe wants becomes a pure trap.
Chunk 3 · The listening keysE5-PRO-RD-?? ⚠

New magic: the keyboard speaks in events

Until today the only letter the mailbox ever mattered for was QUIT. A game needs more: every key press arrives as an event too, and one flat and line catches each. This is the page's one piece of new magic.

    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        if event.type == pygame.KEYDOWN and event.key == pygame.K_1:
            choice = 0
        if event.type == pygame.KEYDOWN and event.key == pygame.K_2:
            choice = 1
Predict Why does each line ask two questions joined by and instead of one? And why does key 1 set choice to 0 rather than 1?
Because a QUIT event has no key at all: the first question, event.type == pygame.KEYDOWN, makes sure we're holding a key-letter before asking which key, and and lets both questions live on one flat line, the Academy's way. And key 1 means flask 0 because the shelf is a list, and Day 1's law never bent: flask numbers start at zero. The keys are numbered for fingers; the flasks are numbered for Python.

Spoil, swallow, or brew: three flat gates

After the listening, three top-level gates judge the frame. Read them slowly; between them they are the entire game.

    if frame < GAME_FRAMES and choice > -1 and choice != NEED_A[target] and choice != NEED_B[target]:

Predict Why does every gate begin frame < GAME_FRAMES and choice > -1: what does each of those two questions rule out? What does and choice not in thrown quietly prevent? And which of your patterns is score = score + 1?
The first question freezes the kitchen at the bell: after frame 1800 every throw is politely ignored. The second stands the gate aside on quiet frames, when nobody pressed and choice still holds its sentinel −1, meaning "no throw this frame." The not in guard stops the same flask from being written on the ledger twice when a key is mashed, the Cauldron Trial's double-dose idea softened from a spoil into a shrug. And the score line is Day 2's counter, wearing a star. Nothing in the judgment is new; the game is your patterns, arranged.

Predict A brew sets flash = 30: for how many frames does the sky glow, in seconds? The star row uses which rule from Day 2? And the timer: the bar starts at 600 and loses 1 every third frame, so where does it stand when the 1800-frame shift ends?
Half a second of glow: 30 frames at 60 per second, drained by an accumulator running backward. The stars sit at 20 + s * 24, the constellation rule from Day 2, one orb per point. And the bar lands on exactly 0: 1800 frames, one pixel every 3, is 600 pixels, the whole bar, and the time_bar > 0 guard parks it there for as long as the window stays open after the bell. The Atelier's % mark turns out to be a clock. When your own shift length changes, this arithmetic is the part you must re-balance, and the hinge is about to make sure you can.
Hinge question · stop here until you're sureE5-PRO-RD-?? ⚠

Judge one order, then re-balance the clock

Part 1: the order orbs show lilac and parchment. Which potion is asked for, which two keys brew it, and what happens the moment you press key 6?
Part 2: you change the shift to GAME_FRAMES = 3600. How long is the shift now, and what must the bar lose its pixel every … how many frames, to land on 0 at the bell?

Part 1: lilac is flask 1 and parchment is flask 4, together only in the Gloamlight Elixir; keys 2 and 5 brew it, and key 6 throws ember, which belongs to neither of this order's slots, so the grey puff takes your progress and the same order waits again. Part 2: a sixty-second shift, and the bar must drop every 6th frame: 3600 divided into 600 pixels. Change the shift without changing the clock and your bar dies at half time, a quiet lie to the player. If you got both, you're ready to run your own kitchen.
The Second Marvel · build brief

Your Cauldron Game

Deadline law Same as the first Marvel: your game plays before you leave. Worst case, revert to the clean engine plus your one safest change. Nobody presents a kitchen that only works in theory.

The four requirements. House law holds: one change per run, prediction spoken first.

1. Your shelf. Rebuild INGREDIENTS and NAMES with your own six colors, keeping the two lists in step.
2. Your menu. Your own three potions across POTIONS, NEED_A, and NEED_B; decide on purpose whether every flask earns a place in a recipe or one is left as a trap.
3. Your shift. A new GAME_FRAMES with the timer bar re-balanced to land on 0, hinge-style, and the seconds defended aloud.
4. Your flourish. One def of your own drawn into the scene: a ladle, a shelf frame, steam over the pot, anything yours.

At First Casting you play one shift in front of the class, brew at least one potion, spoil one on purpose, and narrate which exit ends your game.

Deliberately not covered here: keyboard events enter the apprenticeship on this page, and only as far as the game needs: KEYDOWN plus a key check, joined by and so every gate stays flat. Mouse input and text rendering (pygame.font) remain excluded, which is why all words live in the terminal and all play lives in the window; that split is a design lesson worth saying aloud. Dictionaries would be the adult way to store the menu and remain excluded, so recipes ride parallel lists, the engine's own trick. break stays excluded. The window runs Day 2's watched loop and never closes itself; the bell ends the shift by freezing the gates instead, so the two-exit idea lives inside them: every judgment asks both whether a key was pressed and whether the shift is still on. The spoil is a grey puff and a reset by design: the game's center of gravity is the score, not the wreck.
