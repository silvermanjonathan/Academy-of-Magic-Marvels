The Counted & the Watched

Every casting in the Academy runs one of two ways. A counted casting knows its own length before it begins. A watched casting runs until you end it. Both are on your wand already; today you learn to choose between them on purpose.

COUNT · OR · WATCH

YOU'LL NEED: Days 1–3 complete · a new file saved as castings.py · pygame from Day 2

Chunk 1 · The counted castingE5-PRO-RD-?? ⚠

A lantern that knows its length

One lantern rises. The loop is Day 1's for, so the whole casting can be traced before you run it. The only unfamiliar line is pygame.event.pump(), and it gets its own chunk in a moment.

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Counted Casting")
clock = pygame.time.Clock()

y = 400
for frame in range(180):
    pygame.event.pump()
    y = y - 2
    screen.fill((45, 27, 78))
    pygame.draw.circle(screen, (240, 180, 41), (320, y), 14)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()
Predict How many seconds does this casting last? Where does the lantern end up: compute its final y. And try something while it runs: click the window's close button. What do you expect?
Three seconds, 180 frames at 60 per second, and the lantern ends at y = 400 − 180 × 2 = 40, near the top. As for the close button: the window ignored you. That felt strange, and it should. Hold the feeling until Chunk 3.

A golden lantern rising for exactly 3 seconds,
then the window closes itself. Clicking the X
mid-casting does nothing.
Chunk 2 · The watched castingE5-PRO-RD-?? ⚠

The same lantern, until you say stop

Now the Day 2 form. The lantern wraps and rises again, forever, and the loop watches for one thing: the closing word.

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Watched Casting")
clock = pygame.time.Clock()

y = 400
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    y = y - 2
    if y < 0:
        y = 400
    screen.fill((45, 27, 78))
    pygame.draw.circle(screen, (240, 180, 41), (320, y), 14)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()
Predict How long will this one run? Why does this version need the wrap gate (if y < 0) when Chunk 1's didn't? Click the X: what happens now?
It runs as long as you let it, so nobody can say its length in advance. That's exactly why it needs the wrap: a lantern that might rise for ten minutes needs somewhere to go, while Chunk 1's lantern was only ever going to climb 360 pixels. And this time the X works instantly, because the loop is reading its mail. Which brings us to the real difference.
You should see 
The lantern rising and wrapping, on and on,
until you close the window. The X works
the moment you click it.
Chunk 3 · pump against getE5-PRO-RD-?? ⚠

One checks the mailbox; the other reads the mail

Every window has a mailbox. Clicks, key presses, and the X all arrive there as letters, and a window whose mailbox is never touched gets marked "not responding" by the computer. Here are the two openings side by side. Read them; run nothing.

# The counted casting decides for itself:
for frame in range(180):
    pygame.event.pump()

# The watched casting waits for you:
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
Predict Which casting can say, before it starts, exactly how long it will run? Which one can the person end early? So what must pump() be doing with the mail, given that the X did nothing in Chunk 1?
The counted casting knows its length; the watched casting gives the person the ending. And pump() walks to the mailbox, tells the computer "this window is alive," and walks away without opening a single letter. Your QUIT letter sat unread until the count finished. get() opens every letter, which is how the watched casting hears you. One new call, and now you can read both forms anywhere you meet them; the Academy's own engines all read their mail, but counted spells with pump() are waiting for you in the wild.
Chunk 4 · Misfire on purposeE5-PRO-TR-?? ⚠

The rude window

Take Chunk 1's casting and make one change: range(180) becomes range(1800). Before you run it, find the stop control from Day 2, the square button or Ctrl+C. Then run, wait a moment, and click the X.

for frame in range(1800):
    pygame.event.pump()
Predict How long is this casting now? Will the X close it? How do you actually get out?
Thirty seconds, and the X does nothing for all of them; your letters pile up unread while the count marches on. The stop ritual in the terminal is the real exit. Now you know why every game you've ever played uses the watched casting, and why the Academy's engines do too: a game doesn't know its own length, and a window should always answer its own X. The counted form is honest work for a short demo that announces itself. Make it long and it stops being tidy; it becomes rude.

Choose the casting

Spell A must run for exactly five seconds at 60 frames per second. Spell B must run until the player closes the window.
Which form does each one take, and what number goes in Spell A's range()?

Spell A is counted, range(300), five times sixty. Spell B is watched, and its ending lives on the line running = False. If you reached for a watched loop on Spell A, ask yourself who was supposed to decide when it ends; the answer was the code, so the code should count.
Build brief · The Twin Lanterns

One spell, both castings

Part A, the counted lantern: your own lantern, your color, rising for exactly four seconds. Compute the frame count first and write it in your Grimoire before you type it.

Part B, the watched lantern: the same lantern in the watched form, wrap gate included, running until closed.

Suggested start: Part A from Chunk 1, one change per run. House law holds: before running any watched casting, point at the line that turns it off.

import pygame

# --- Part A: the counted lantern (4 seconds = 240 frames) ---
pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("Counted Lantern")
clock = pygame.time.Clock()

y = 400
for frame in range(240):
    pygame.event.pump()
    y = y - 1
    screen.fill((16, 8, 34))
    pygame.draw.circle(screen, (196, 120, 255), (320, y), 14)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()

# --- Part B: the watched lantern (until closed) ---
pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("Watched Lantern")
clock = pygame.time.Clock()

y = 400
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    y = y - 1
    if y < 0:
        y = 400
    screen.fill((16, 8, 34))
    pygame.draw.circle(screen, (196, 120, 255), (320, y), 14)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()
Part A ends with the lantern at y = 160; check yours against your Grimoire math. Run the parts as separate files if you prefer; each is a complete casting.
